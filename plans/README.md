## Dependency notes

- **002 requires 001.** Re-quantizing and vocabulary-trimming the weights changes model
  output. Without a scored harness there is no way to tell a 60% size cut with no accuracy
  loss from a 60% size cut that quietly stopped finding Brazilian names.
- **005 requires 001** for the same reason: batching changes padding and attention masks,
  which can silently change scores. The harness is the regression gate.
- **007 requires 001** to prove the structural path finds strictly more than the prose path.
- **003, 004 and 006 have no dependencies** and can run in parallel with 001.

## What the research changed

Two assumptions from the first pass did not survive checking. Recorded here so they are
not re-proposed:

1. **"GLiNER2-PII is roughly half the size of the current model."** False.
   `fastino/gliner2-privacy-filter-PII-multi` ships `model.safetensors` at **1.23 GB** fp32
   (~307M params) against `gliner_multi_pii-v1`'s 1.16 GB (~280M). It is marginally
   _larger_, and there is **no ONNX export in the repo** at all. Its advantage is recall
   (.75/.69 vs .32/.35 on SPY) bought with poor precision (.35/.37); the model card admits
   it "tends to over-predict `name` entities, confusing common nouns and organization names
   with people." For an app that paints black boxes automatically, that trade is bad
   _unless_ plan 003 lands first. It is a candidate to measure under 001, not a swap to make.

2. **"Replace tesseract.js with PaddleOCR in the browser."** Not ready for this repo's
   languages. `ppu-paddle-ocr`'s PPU checkpoints cover zh/en/ja/ko only; `pt` and `es` fall
   back to RapidOCR models. The most-cited browser port (`siva-sub/client-ocr`) has 12 stars,
   no releases, and uses **WebGL, not WebGPU**. The real path would be exporting
   `PaddlePaddle/latin_PP-OCRv5_mobile_rec` yourself via `paddle2onnx` with the
   Latin-specific character dictionary (using `ppocrv5_dict.txt` decodes á, ã, ç, ñ and õ
   wrong). That is a multi-week project with a real chance of ending worse than Tesseract on
   flat scans. **Deferred.** Revisit only after 001 exists, so the comparison is a number
   rather than an argument.

## Direction findings (options, not defects)

These are for the maintainer to weigh. Not planned.

- **The review step is table stakes, and the local-only story is the real moat.** Of seven
  free PII redaction tools surveyed in 2026, only two processed entirely in the browser
  without uploading; meanwhile a human-in-the-loop review interface with approve/reject
  actions is described across vendor comparisons as the distinguishing capability.
  SafeRedact, PII Blackout and RedactProof all ship one; SafeRedact only achieves it by
  sending extracted text and coordinates to a server. localveil can have both. That is
  plan 003.
- **Two-threshold detection only makes sense with 003.** Once a human confirms spans, the
  auto-redact floor's job moves to the reviewer: auto-apply above 0.35, surface 0.15 to 0.35
  as "check this." Recall rises without dumping false positives into output files. This is
  why 003 is priced as L rather than M, and why the higher-recall models above become usable
  at all.
- **Folder-at-a-time redaction.** The File System Access API would let the web app do what
  the CLI does (`--jobs`, many files) without a terminal. The worker pool already handles the
  concurrency. Mostly a UI and permissions problem.
- **Vocabulary trimming is a repeatable asset, not a one-off.** Whatever detection model wins
  under 001, the trimming pipeline from 002 applies to it unchanged. Build it once.

## Findings considered and rejected

- **Swap to `knowledgator/gliner-pii-{base,large}-v1.0` on the strength of its published
  numbers.** Its UINT8 ONNX at 197 MB against the current 894 MB is genuinely attractive and
  it uses quantization-aware pretraining, which is the right answer to the int8 collapse this
  repo already hit. But the HF card tags it **English**, never claims Portuguese, and its
  benchmark table is self-reported on its own synthetic dataset. Not rejected outright:
  rejected as a _blind_ swap. It is the first checkpoint to run through 001.
- **Blanket-indexing OCR words below confidence 60.** Already refuted in a prior review; it
  breaks the tested tofu-page protection in `packages/ocr/src/readable.ts`. The scoped
  variant (always index digit-bearing words so check-digit patterns can fire) survives and is
  folded into plan 007's maintenance notes.
- **Replace the greedy NMS in `gliner-decode.ts` with Viterbi decoding.** Real, but its
  payoff is unmeasurable today and it competes for the same reviewer attention as 003.
  Revisit after 001 gives a recall number to move.
